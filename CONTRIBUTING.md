## 更新日志与发行说明 / Changelog and release notes

### 中文

**每一次发布，两处都要写：仓库里的 `CHANGELOG.md`，以及 GitHub release 的正文（发行说明）。**
它们是同一份东西的两处落点，不是两件事——只写一处，就会出现"仓库里的日志是双语的、而用户看到的发行页是单语的"。
标签注解同样如此。

- **中英双份**：中文一节 `## 更新内容` ＋ 英文一节 `## What's changed`，**两节条目一一对应**。
- **极简**：一条一行，符号标性质——`*` 核心功能 / `+` 小功能添加 / `#` 修复；外层用代码块包住。
- **只写「改了什么」**：不写原理、不写实测数据、不写过程、不写注意事项、不写用法提示；
  不带安装说明、不带 MD5、不带「详见某文档」；主功能不重复。
- **两处都在推之前改完。**

### English

**Every release writes both places: the repository's `CHANGELOG.md` and the GitHub release body.** They are two
places for one thing, not two documents — writing only one leaves the changelog bilingual and the release page
monolingual. The same holds for tag annotations.

- **Chinese and English**: a `## 更新内容` section followed by a `## What's changed` section, **entry for entry**.
- **Minimal**: one line per entry, marked `*` (core), `+` (small addition) or `#` (fix), wrapped in a code block.
- **Only what changed**: no rationale, no measurements, no process, no caveats, no usage notes; no install
  instructions, no checksums, no "see …". The main feature is not repeated.
- **Both places are updated before pushing.**
